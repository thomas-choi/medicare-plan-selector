## New Issue 7 — Empty assistant chat reply renders as an endless "…" (Medium, CODE)

- Where: `backend/selector/agent/validator.py:77` (`validate()` has no non-empty-text check) →
  `backend/selector/agent/orchestrator.py:129-135` (empty text passes validation and is returned
  as the turn result) → `backend/selector/api/routes.py:324` (empty text persisted) →
  `frontend/src/App.tsx` chat area (empty assistant bubble shows the pending "…" placeholder).
- Observed: chat turn "Explain H0028_028_0" in the browser UI. API log:
  `06:29:53 validator rejected answer: 2 problems`, then `POST /api/chat status=200 ms=20528`.
  Stored assistant message: `content: ""` with 11 citations (`GET /api/session`).
  UI showed only "…" plus source chips and never recovered (waited >3 min, page reload kept it).
- Reproduce: send a chat message whose second model attempt (after a validator rejection) comes
  back with empty/whitespace-only text. Intermittent and model-dependent — the follow-up turn
  "Compare plans for me" in the same session returned a full ranked table, and a curl-level turn
  returned the deterministic fallback text correctly.
- Hypothesis (high confidence): on the retry round the model returns no text content; since
  `validate("")` finds no problems it is accepted as `ok`, so the orchestrator returns an empty
  reply instead of falling through to `deterministic_summary`.
- Fix suggestion: treat empty/whitespace-only model text as a validator rejection in
  `orchestrator.py` (e.g. `if not text: treat as rejected`), so the existing
  `deterministic_summary` fallback always produces content. Optionally have the frontend replace
  an empty assistant bubble with an error/retry notice.
